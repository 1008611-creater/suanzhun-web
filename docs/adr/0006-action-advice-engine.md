# ADR 0006：行动建议引擎（事业 / 婚姻 / 八宅落地 / 姓名优选）

- 状态：已采纳
- 日期：2026-09-18

## 背景

0.8.0 之前，结果页七块内容全部是「结构描述」：四柱是什么、五行几分、命卦哪个方位、
五格各是多少。用户看完知道自己「中和偏弱、用神火土、命卦巽、总格 46 凶」，
但拿不到一句能落地的动作——不知道往哪个行业走、什么时候是感情窗口、床头该朝哪、
名字要不要改。

同时，用户在前事验证环节给出的真实反馈（学历、家庭结构、感情时间线）表明：
他要的是「可验证 + 可行动」，不是又一份术语堆砌。

## 决策

新增四个纯函数，输入都是已有的排盘结果 + `nowYear`，输出结构化建议：

| 函数                         | 说明                                                     |
| ---------------------------- | -------------------------------------------------------- |
| `career(p, nowYear)`         | 十神结构定发力方式，用神定行业属性与方位，大运定阶段节奏 |
| `marriage(p, nowYear)`       | 配偶宫十神定相处模式，配偶星定强弱，流年动象定应期窗口   |
| `layoutPlan(bazhai, ws)`     | 把八宅吉凶方位翻译成床头、书桌、神位、次选位与回避位     |
| `nameAdvise(name, ws, opts)` | 只改「名」不动「姓」，枚举笔画候选并排序                 |

### 1. 十神力量口径与 `bazi.js` 保持一致

`shiShenPower()` 复用 `p.wx.detail` 的权重（藏干已按本气/中气/余气 0.6/0.28/0.12 加权），
用与 `bazi.js` 同一个 `shiShen()` 判定十神，再归并到比劫/食伤/财/官杀/印五组。
`tests/advice.test.mjs` 直接对拍 `BaZi.shiShen()`，两边口径不允许漂移。

### 2. 事业与婚姻接收 `nowYear`，引擎不读系统时间

`analysis.js` 是 UMD 纯函数模块，`tests/smoke.test.mjs` 约束它不得依赖浏览器，
可复现性也要求同样输入永远同样输出。所以大运定位与应期窗口都靠调用方传入 `nowYear`，
`scripts/verify.mjs` 新增契约：`analysis.js` 里不得出现 `new Date()` / `Date.now()`。

### 3. 姓名优选：硬门槛 + 不为了改而改

- 硬门槛：人格与地格为凶数的候选直接丢弃，不进推荐列表。
- 排序：五格吉数 → 三才顺逆 → 格五行是否落在用神。
- 只改「名」不动「姓」，天格（姓的笔画 + 1）在候选里必须恒定。
- 现名若无硬伤，文案明确说「可以不改」，避免制造焦虑式推销。

### 4. 每块建议都带免责说明

事业块写明「不构成择业或投资建议」，婚姻块写明「不做正缘承诺」，
姓名块写明五格剖象法流派不统一、不要为补数硬凑生僻字。
这类产品最容易越界成确定性承诺，文案边界必须和算法一起进代码。

## 后果

- 结果页新增四块卡片，插在八宅与姓名两块之后，沿用既有 `el()/kv()/esc()/jClass()`
  与设计令牌，未引入新依赖。
- `tests/advice.test.mjs` 新增 13 项回归：十神口径对拍、比例自洽、事业大运定位、
  越界年份返回 null、婚姻评分有界与应期窗口、女命取星不同、八宅八方位齐全、
  床头不落绝命五鬼、姓名候选硬门槛与降序、未收录字形不抛错、天格恒定、
  格五行与三才判定。
- `scripts/verify.mjs` 新增 4 项契约：四块都接进结果页且引擎有导出、
  结果页含四个标题、事业与婚姻接收 `nowYear` 且引擎不读时钟、建议带免责说明。
- 建议仍然只基于命理结构，不替代现实判断；后续若引入更多流派，
  必须新增 ADR 说明取舍，不静默替换口径。
