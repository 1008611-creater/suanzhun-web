# ADR 0005：流年窗口跟随当前年份，结果页补下一步转化

- 状态：已采纳
- 日期：2026-09-18

## 背景

真实浏览器复现两个内容缺陷，都不是样式问题，是「用户走到关键位置却拿不到东西」。

**1. 流年表对早年生人整块空白。** 引擎里 `liuNian` 只生成出生次年起 60 年，
结果页却把窗口写死成 `2026 – 2035`。实测：

```
出生 1930 -> liuNian 1931..1990，窗口命中 0 行
出生 1965 -> liuNian 1966..2025，窗口命中 0 行
出生 1975 -> liuNian 1976..2035，窗口命中 10 行
```

也就是 1975 年前出生的人，点开「流年运势」只能看到一行表头。

**2. 结果页在最高意图时刻没有任何下一步。** 整页 `<a>` 数量为 0，`app.js` 里既没有
联系方式也没有保存入口，七块分析读完直接进页脚。而 PRD 的核心用户路径第 5 步是
「通过微信联系人工详批」。用户刚看完自己的一生结构、信任度最高，却无处可去。

## 决策

**1. 流年窗口跟着当前年份走。** 结果页窗口改为 `nowYear – nowYear+9`，而不是写死。

**2. 引擎不读系统时间。** `bazi.js` 保持纯函数、结果可复现，年数由调用方传入：

```js
function lnYears(opt) {
  var want = Number(opt && opt.liuNianYears);
  return isFinite(want) && want > 60 ? Math.floor(want) : 60;
}
```

下限固定 60（一个完整甲子），调用方 `app.js` 按 `当前年份 + 10 - 出生年` 传参。
这样 1965 年生人也能覆盖到当下之后，而引擎本身仍然与时间无关——
`tests/smoke.test.mjs` 的「计算模块保持无浏览器依赖」与可复现性约束都继续成立。

**3. 结果页补「下一步」卡片。** 含微信号 `ANS_0912` 与复制按钮、保存/打印报告、
修改信息重排三个动作，对应 PRD 核心路径第 5 步。

**4. 打印样式。** 加 `@media print`：只留报告本体，隐藏 hero、表单与非结果卡片，
卡片去阴影去背景、`break-inside:avoid`，深色芯片反白为黑字白底。

## 踩过的坑：`!important` 的层叠顺序

第一版打印样式写成 `.hero,...{display:none}`，同时 `.card{display:block!important}`。
带 `!important` 的那条赢，于是打印预览里表单和 hero 全都还在。
隐藏规则同样需要 `!important`，且必须与显示规则区分选择器层级。
已用 `page.emulateMedia({media:'print'})` 在真实浏览器验证：`hero=表单=下一步=none`、
`#result=block`，导出 6 页 PDF。

## 后果

- `scripts/verify.mjs` 新增 4 项契约：流年窗口跟随当前年份而非写死、
  流年年数由调用方传入且引擎有下限、结果页有下一步转化卡片、结果页有打印样式。
- `tests/bazi.test.mjs` 新增 3 项回归：默认 60 年且不依赖系统时间、
  早年生人可通过 `liuNianYears` 覆盖到当前年份之后、小于 60 或非法值回退 60。
- 4 项闸门全部做过反向验证（改回写死窗口、删微信号、改函数名），确认会真的失败。
- 后续新增结果页动作时，同步更新本 ADR 与对应契约。
